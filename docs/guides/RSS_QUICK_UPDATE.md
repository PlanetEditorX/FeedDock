# FeedDock 1.17.12 RSS 候选搜索与快速更新

## 使用方式

点击订阅卡片的“更新 RSS”，FeedDock 会进入该订阅编辑页并打开跨站候选窗口。

默认身份来源顺序：

1. 当前站点番剧 ID；
2. Bangumi Subject ID；
3. 参考标题；
4. TMDB 规范标题；
5. 手动规范标题；
6. 订阅名称。

搜索范围：Mikan、ANI.BT、Anime Garden。结果按站点和字幕组列出，并显示最近资源数量、匹配原因和原站详情链接。

每个候选提供：

- **填入主 RSS**；
- **填入备用 RSS**；
- **保存并检查**：只更新并检查当前订阅。

编辑页仍保留“仅保存 RSS”和“保存 RSS 并立即检查”。

## 空源处理

当 RSS HTTP 请求成功但没有条目时，日志会提示重新搜索 RSS，不再在 INFO 级别展示 Python Traceback。DEBUG 级别仍保留堆栈。

备用 RSS 同样必须包含条目才会被视为可用。

## 请求控制

候选搜索只在用户主动点击时执行，不加入后台轮询。每个站点只取少量最相关番剧，再列出该番剧下的全部字幕组 RSS，避免一次操作产生无界请求。


### 主备 RSS 检查（修复版）

- 在“更新 RSS”候选列表点击“设为主 RSS 并保存”或“设为备用 RSS 并保存”，会直接写入数据库，并触发该订阅检查（启用时）。无需再打开隐藏的表单点击保存。
- **主 RSS 正常且含有资源时始终使用主 RSS**；主 RSS 连接失败、解析失败或无条目时才尝试备用 RSS。备用 RSS 并不与主 RSS 轮询合并。
- “订阅详情”显示已保存的两个 URL 与最近一次成功使用的来源。编辑页可分别“测试主 RSS”和“测试备用 RSS”；独立测试不会触发下载，测试的是已保存地址。
- 更换任一 RSS URL 将清空旧的 RSS 异常记录，订阅进入“待检查”状态；实际刷新后如仍失败，会重新显示新错误。编辑名称而不更改 URL 不会清除真实错误。
